# 禅道 API 实例配置与操作契约 v1

日期：2026-11-03。状态：已核对旧工作台方法、实际关闭回执和现有登录／查询源码；形成首个实例配置的实现依据。本轮未登录禅道、获取 Token、上传图片、读取或修改线上 BUG。历史实例证据不代替新部署的身份、权限与实际验收。

关联：[3.6 BUG](../stages/bug-management.md)、[3.7 复验](../stages/bug-retest.md)、[工具清单](../tool-adapters.md)、[来源和验证范围](../../verification/adapter-contracts-20261103.json)。

## 1. 分离协议、认证与项目映射

实例配置保存服务 origin／API 前缀、API 版本、认证方式引用、支持动作、事务上下文获取方式、请求编码、字段映射与验证依据。项目配置另保存产品／项目／执行／计划／版本／需求及指派映射。不要把公司地址、账号、历史 BUG ID 或某次字段值写进通用实现。

首个实现目标为有历史实证的 v1 配置。v2 单独作为协议扩展，不能在 v1 失败后自动换方法重发写请求。配置中有路由也不等于该身份在当前实例具有权限。

## 2. 两种认证方式

| 方式 | 已有依据 | 实施限制 |
| --- | --- | --- |
| 已登录同源会话 | 原实例通过同源 fetch、credentials:include 调用 v1，身份用 GET user 核对；上传／创建及后续回读有记录 | 浏览器仍使用专用 headless；保持同一会话与操作上下文，不导出或复制 Cookie，不走正常表单创建 |
| 独立 Token 客户端 | AsyncTest 查询适配器以 POST tokens 取得凭证，后续用 Token 请求头，拒绝重定向 | 读取／登录源码不证明上传创建已验收；独立客户端的文件关联和关闭需单独验证，不复用浏览器成功结论 |

缺身份时使用已授权凭据引用和实例提供的登录方式。safeStorage 密文不当密码，不解密打印或复制为公共配置。原实例允许 Cookie 会话不代表所有禅道都不需要 Token。认证失败不得悄悄换高权限身份。

## 3. v1 操作基线

路径相对于已核对的 `/api.php/v1`，实际 host 由配置提供：

| 动作 | 方法与路径 | 编码／输入 | 完成依据 |
| --- | --- | --- | --- |
| 当前身份 | GET `/user` | 本轮有效会话或已支持认证 | 返回账号与本轮预期一致 |
| 获取 Token | POST `/tokens` | 受控账号与密码，源码使用 JSON | 有实际 Token 回执，后续身份与权限核对；本轮未调用 |
| 上传标注图 | POST `/files?uid={uid}` | multipart，字段 imgFile；边界由客户端生成 | 文件 ID／地址、实际图像读取及源摘要 |
| 创建 BUG | POST `/products/{productId}/bugs` | 已核对字段、steps 图片 HTML、同一事务 uid，历史路径使用 JSON | 唯一 BUG ID，字段及附件正式关联回读 |
| 读取 BUG | GET `/bugs/{bugId}` | 已核对目标身份 | 实际正文、字段、状态及附件 |
| 补齐字段 | PUT `/bugs/{bugId}` | 原授权中的最小变更，按实例编码 | 变更确实保存，其他必要字段保持 |
| 关闭 BUG | POST `/bugs/{bugId}/close` | 历史实例回执明确为 multipart/form-data：comment + uid | 状态 closed、动作记录／备注及附件关联回读 |

关闭基线来自旧仓库四条 2026-10-29 的实际回执，均记录单次 POST、HTTP 200、closed、备注一致和附件关联；不是本轮新关单。它补足了此前只有官方候选路由的缺口，但不能推导所有 v1 部署都使用相同 multipart 参数。纯文字关闭和其他认证模式也要遵守当前实例的实际契约。

官方 [v1 修改文档](https://www.zentao.net/book/api/723.html)列出 PUT 及常见字段；公司实例曾忽略创建时的 plan，随后通过同一对象的最小 PUT 补齐成功。这是实例差异，应保存为适配特性。官方关闭页本轮仍未成功全文读取，精确实例依据优先来自已核对的历史回执，不能声称审计了线上部署源码。

## 4. 事务上下文和图片

原创建路径通过获授权的新建上下文读取 uid，再保持同一认证会话完成 REST 文件上传和建单。上下文 URL／来源由实例配置或真实页面提供，不拼造固定表单地址、不拿用户正在编辑的表单 uid、不复用历史值。获取上下文的读取不等于业务写入完成。

关闭中新增图片也需要本次上下文及匹配的 uid；历史回执给出最终编码，但未完整描述通用 uid 获取实现。适配器应明确提供该输入来源，未取得可靠来源时停止相应上传和关闭，不生成随机字符串冒充服务器上下文。

每张图记录源摘要、文件 ID、返回地址和当前阶段；BUG 保存后确认 files 中对应的 objectType／objectID，并在保存及重新读取后绕缓存核对真实图像类型、解码尺寸与适用摘要。可访问者独立账号验证按 3.6 的接入／变化场景安排，不能把上传者读取当成同事可见。

相对图片 URL 解析到同一已核对实例，取实际服务返回的地址，不硬编码文件编号或跨站转发凭据。Markdown 本机路径和 Base64 不直接当作最终正文图片；在结果段内渲染标注图，期望在后。

## 5. 单次派发、修补与结果不明

派发前保存源稿版本、目标对象映射、认证和事务引用、文件摘要及操作 ID。创建后只有一个远端 BUG 身份；修字段、图片或计划都处理同一对象，不再次创建。上传、创建、补齐、关闭和回读分别登记，上传成功不等于正式绑定。

超时或断线先核对当前对象、动作记录和附件，保留未知状态；不能因当前列表没找到记录就判定未应用。仅凭标题相同也不能认定同一创建，必须结合实际关联线索。没有可用远端幂等键时，禁止宣称任意网络故障下可保证恰好执行一次。

关闭前核对最新状态、修复依据和授权。已被他人关闭时报告实际状态及归属，不把别人的动作记成本次关闭；失败或阻塞不自动关闭，也不替开发先置为已解决。已经确认同一操作成功时只补回执，不再次派发。

## 6. 实施前检查与验收范围

实施可以从参数化 v1 路由、两种认证接口和持久化操作记录开始；具体实例字段、事务上下文来源及当前权限在实际任务准备时核对。新实例缺失这些输入只阻塞相应真实动作，不阻塞本地 BUG 草稿或其他独立工作。

验收使用另行授权的测试项目与专用数据，覆盖字段准确、单次创建、图像持久化、补齐计划、条件关闭、取消／权限拒绝及未知写入回查。现有历史关闭回执未做独立账号复核，不把这一项标成已通过。Token 模式与会话模式分别记录验证结果，任何失败不自动切 UI 提单或显式浏览器。
