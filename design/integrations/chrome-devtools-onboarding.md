# Chrome DevTools MCP 接入与隐式调用

日期：2026-11-02。状态：用户明确提出推荐工具、隐式调用和缺失时帮助安装的要求，本文记录后续实施规则；具体跨宿主安装器、无界面适配和真实验收尚未实现。本轮只查阅官方资料和更新设计，没有安装依赖、修改客户端配置或启动 Chrome。

## 用户确定的默认行为

1. 测试执行强烈推荐 Chrome DevTools MCP，默认优先选用；用户明确指定其他工具时尊重该选择，不能借换工具绕过无界面约定。
2. 使用 Chrome DevTools MCP 时，任何时候默认隐式调用，即真正的 headless Chrome：独立浏览器实例及数据目录，不显示或抢占桌面窗口。截图、快照、进度和证据仍可正常提供。
3. 只有用户明确要求显式执行时，才可在其指定范围使用可见浏览器。调试、登录、验证码、上传下载困难不自动构成切换许可。
4. 用户没有安装或接入时，由 Agent 识别宿主、检查依赖并帮助完成必要安装与配置，不默认让用户自行研究命令或配置文件。已安装且符合模式的连接优先复用。

这些是用户明确为 VeriForge 设定的默认要求，不是把原工作台的局部实验自动推广为已验证通用能力。当前仍按“完整设计后再实现与测试”的顺序推进。

## 怎样向用户说明

> 我会优先使用 Chrome DevTools MCP，在独立的无界面 Chrome 中操作，保留进度和截图，不干扰你日常使用的浏览器。工具尚未接入时，我会检查当前客户端并完成必要配置；需要你参与的系统授权或客户端操作会说明原因。

纯问答时只说明方法。进入已授权的实际接入或测试任务、需要此能力时，才检查和配置；本设计讨论本身不触发安装或业务测试。

## 自动检查与安装流程

1. **识别宿主与执行位置。** 确认当前 Agent 所在客户端、系统、可用 MCP 配置方式、浏览器实际运行位置和配置权限，不固定为 Codex 或某个作者电脑路径。
2. **区分已安装、已配置和当前可用。** 查实际工具列表及必要配置。工具暂时不可见不等于未安装；配置存在但会话未加载时处理加载／连接问题，不循环重装。
3. **核对官方依赖与来源。** 按安装时的官方资料检查 Node.js、npm 和 Chrome，选择可信官方来源及兼容版本。已有依赖直接沿用；确实缺少的在授权范围补齐，不覆盖用户其他项目依赖或系统设置。
4. **准备专用 headless 配置。** 显式启用 headless，保留用户已有 MCP 和日常浏览器配置。已有连接为可见模式时新增或选择独立的无界面入口，不将普通连接静默改写或拿来直接调用。
5. **适配当前客户端并安装。** 使用宿主实际支持的配置／安装入口，把命令、参数和所需环境配置落到正确位置，保存实际版本及必要变更记录。不要求用户重复批准已授权的常规接入；遇系统权限、宿主批准、组织限制或必须手工加载时说明来源，只请求必要的一步，不绕过限制。
6. **验证模式与最小连通性。** 进入后续接入阶段后，核对有效启动参数、目标实例与隔离目录，再用空白页等不含业务数据的最小只读动作确认工具可用。只有 MCP 握手或配置保存不能证明 Chrome 已以 headless 启动，也不能代表业务测试通过。

版本在安装时解析并记录，执行批次固定实际工具和能力版本；不因上游自动更新就把旧模块验证范围直接沿用。任何需要重启的变更先保存当前任务和未知操作，只重启本任务负责的资源。

## 参数与隔离依据

本次只读核对了官方 [README](https://github.com/ChromeDevTools/chrome-devtools-mcp) 和 [配置说明](https://github.com/ChromeDevTools/chrome-devtools-mcp/blob/main/docs/configuration.md)。它们说明了 Node.js LTS、Chrome 和 npm 的接入要求，以及通过 MCP 客户端启动服务的方式；具体版本在真正安装时再次核对。

官方配置说明列出以下能力：

| 参数 | 官方含义与本设计的用法 |
| --- | --- |
| `--headless=true` | 无界面运行；官方默认 false，因此本设计要求显式开启 |
| `--isolated=true` | 临时独立用户数据目录，浏览器关闭后清理；适合无需持久登录状态的专用批次 |
| `--user-data-dir` | 指定用户数据目录；需持久会话时使用受控专属目录，不使用日常个人 profile |
| `--executable-path` | 指定 Chrome 可执行文件；按当前系统实际安装位置设置 |

临时目录与持久目录策略按任务需要和当前工具约束选择，不盲目组合参数。独立目录、登录身份和资源引用按项目／环境／任务管理；临时目录关闭会清理，不能承诺凭它恢复旧登录态。登录本身是测点时仍执行真实认证链路，不用恢复登录态替代验收。

服务别名含 headless 不构成运行模式证明；连接已有浏览器时同样核对该实例实际无界面且归本任务所有。不默认自动接管用户正在使用的 Chrome，也不把自己的 headless 标志当成已有可见实例已转换。切换或重连后重新核对目标和模式。

本轮参数只作为设计依据，没有生成可直接套用所有宿主的配置文件。官方示例和旧实验不自动成为用户的实际命令、路径、权限或版本。

## 任何 Chrome DevTools 调用都遵守的边界

约束覆盖执行前检查、页面取证、模块验证、正式测试、失败排障和修复验证中的 Chrome DevTools 浏览器操作。通过 UI 模块间接调用时也遵守同一模式，不允许模块自行打开可见窗口或改启动参数。

显式例外由用户明确表达，例如“这次显示浏览器，我想看过程”；记录适用任务及范围，未覆盖的调用继续默认 headless。说“看看结果”“给我截图”不等于要求显示浏览器窗口；headless 中取得的截图可以直接展示。

若当前连接是可见模式、无法确认目标模式或 headless 不支持某步骤，先停止相应浏览器动作并说明具体阻塞，继续不依赖它的工作。只有用户明确选择显式执行才切换；没有回应不视为授权。不能为了诊断而先弹出窗口再补说明。

切换模式在明确断点处理，保留业务数据和未知写入，不因新浏览器会话而重复提交或审批。用户授权可见的范围结束后恢复默认选择规则，不擅自关闭用户自己的浏览器。
