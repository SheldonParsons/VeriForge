## 核心能力与依赖

采用核心 `scripts/annotate.py` 对已有真实截图确定性叠加标记；默认输出 PNG 标注副本及 `.evidence.json`。输入为源图片、包含 annotations 的 JSON 对象和新输出路径，每条标注含 box 与 text，坐标来源及画布空间如实注明。

核心需要 Python 3.10+、Pillow==12.3.0 和覆盖所用文字的字体。VeriForge 本身的 Python 3.11+ 基础运行环境满足其 Python 下限，Pillow 作为需要标注时才安装的可选能力依赖，字体按目标机器实际提供，不能声称当前都已齐备。源包不捆绑字体或 Pillow。

完整 CLI 及规格见 [上游说明](../../vendor/screenshot-annotator/0.1.0/README.md) 和 [标注格式](../../vendor/screenshot-annotator/0.1.0/references/annotation-format.md)。源图和已有输出不覆盖，产物须查看；源摘要、输出摘要及定位来源保留。文件名和说明不会自动脱敏，脚本也不自动判断图片真实性或 BUG 是否成立。

可选的 Playwright capture-target.cjs 仅作为上游源码保留，首版不引入其浏览器控制依赖。截图采集继续走 Chrome DevTools MCP 默认 headless，标注核心接收截图和坐标即可，不额外创建浏览器、登录或点击业务页面。

## 后续直接内置方式（方案）

不要求使用者另行全局安装一个截图 Skill。后续在 VeriForge 实施阶段，将固定的核心绘图代码、规格及许可随包提供，由内部证据入口调用；当前 vendor 是来源基线，不是已经安装到发布包的能力。

VeriForge 外层负责：

1. 将原图与任务、场景／步骤、采集时间、环境、页面、角色和截图方法关联。
2. 根据真实观察选标注区域、文字和样式，区分 DOM 定位与视觉估算；同一完整视口的缩放坐标才按当前工具契约换算。
3. 输出新标注图，核对未覆盖源文件，并查看标注是否准确、可读、不遮挡关键现象。
4. 验证 `.evidence.json` 的源图／副本摘要与实际文件一致，再将标注图放进 BUG 的结果段。
5. 对每条 UI BUG 检查至少一张真实截图及标注副本是否齐备；不把合成示例、生成式导航示意或工具成功返回当成业务证据。

每份 UI 证据保留 original.png、annotations.json、annotated.png、annotated.evidence.json，并关联执行记录。颜色按项目或用户约定设置，不把导航指引的样式强制用于所有 BUG。

2026-11-03 用户补充 BUG 文案应简洁、优先截图与标注。外层 Agent 用短标签说明关键位置与差异，需要展示前后变化时组织有顺序的对比图；正文保留必要条件、动作和期望，不重复长篇描述画面。标注不能遮住关键值，也不把长段正文挤进图片；精确输入等需要复制的内容仍保留文字。此约定由外层写作和核对落实，不修改上游源码或让绘图工具静默删减语义。

实际接入需要补充依赖检查、调用回执、错误及未知产物处理、打包许可和验收。可选浏览器适配器未提供全页长图或裁剪坐标转换，核心 renderer 只接受与源图匹配的坐标；不能声称 VeriForge 已具备这些采集适配。隐私打码不在当前工具能力内，有需要时单独处理并保留来源。两个输出文件在断电或强杀时不保证同时完成，恢复时核对实际产物而不是直接重复覆盖。
