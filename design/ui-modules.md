# UI 模块规范 v1

日期：2026-11-02。状态：按用户“那 6 件事情由你来决定并且确定下来”的明确授权，由 Agent 决策定稿，作为后续实施基线；不是用户逐字段审阅，也不表示已实现或真实验证。本轮不改运行器、不创建业务模块、不操作页面、不更新 Skill 包版本。

本规范承接 [3.2 页面取证](stages/page-discovery.md)、[项目归属](project-scope.md)、[共享原则](shared-resources.md) 和 [协作约定](collaboration.md)。早期建议保存在 [讨论记录](ui-modules-discussion.md)，冲突处以本规范为准。

## 六项决定

| 事项 | 决定 |
| --- | --- |
| 最小内容 | 可执行模块由机器可读契约、实现及独立验证记录组成；页面资料与本轮数据分别维护 |
| 划分粒度 | 以可独立复用、可判断结束的一项操作为基本单元；紧密动作不拆碎，填写与持久化提交分开；流程只组合已有能力 |
| 存放与检索 | 项目 UI 资产、显式共享 UI 资产、需求运行证据三处归属；生成索引按需检索，已有目录映射接入 |
| 形成与验证 | 观察资料→查重和定边界→参数化实现→限定条件真实验证→登记复用；无页面时允许资料草稿，不登记虚假可用能力 |
| 复用 | 按精确能力身份、版本摘要、上下文、行为和测点选用；默认简洁回执，必要断言保留；业务预期由用例提供 |
| 更新 | 保留不可变版本依据，按变化范围补采、修订和重验；更新引用并保留旧结果，不让活跃任务静默换实现 |

## 1. 最小内容与结果契约

### 1.1 可执行模块的契约

第一版使用 JSON，文件名为 `capability.json`；契约版本 `schema_version: 1` 独立于工作空间数据格式和模块实现版本。以下为确定的字段与语义，验证器及适配器在实施阶段实现。

| 字段 | 必需内容 |
| --- | --- |
| `schema_version`、`id`、`version`、`title`、`kind` | 稳定 ID、实现版本、可读标题；kind 为 component、action 或 flow |
| `scope` | 所属项目／共享范围、系统、支持环境、页面资料引用和已知适用限制；产品版本可未知，但不能因此宣称覆盖所有版本 |
| `entry` | 实现文件、入口、运行方式、适配器及所需工具能力；必须指向实际存在且当前适配器支持的实现 |
| `preconditions` | 身份、目标页面、业务状态、数据与未提交表单等开始条件；每项有稳定检查 ID 和含义 |
| `inputs` | 参数名称、类型、是否必填、约束和含义；不对改变测试语义的参数设置隐藏默认值 |
| `outputs` | 返回字段的类型和含义，包括目标标识、实际数据、读取范围／完整性及结束页面状态 |
| `effects` | 业务效果 read、draft 或 write，以及导航、展开、筛选重置等 UI 影响；实际自动保存归 write |
| `completion_checks` | 能证明本操作完成的检查点，明确身份、对象、就绪和必要回读，不用 HTTP 200 代替业务保存 |
| `recovery` | 有界等待、允许的读取重试、失败结束状态和写入未知时的回查方式；没有声明时不自动重试 |
| `dependencies` | 依赖的能力 ID、精确版本和内容摘要；没有依赖时为空，禁止循环依赖 |
| `limits` | 未支持的入口、角色、业务状态、读取范围和副作用限制；没有特别限制时显式为空 |

模块 ID 采用 `<项目ID>.<系统ID>.<业务域>.<操作名>`；共享能力采用 `shared.<业务域>.<操作名>`。不包含需求编号、账号或环境。同名能力不自动相互替代；既有项目 ID 通过目录映射兼容接入，不在迁移时批量改名。

运行上下文由调用方提供，至少绑定项目、需求／任务、运行 ID、系统、环境、产品版本信息、预期身份引用、隔离会话和资源引用。上下文不写死进模块，也不能从一个全局“当前账号”推测。凭据由既有本机机制读取，不进入契约或普通回执。

验证记录独立于契约及代码，记录模块版本、源文件摘要、依赖摘要、日期、环境、产品版本／可观察页面特征、角色及数据条件、检查范围、实际结果和证据引用。保留多次记录，按本次上下文判定是否适用，不能用一个全局 verified 覆盖所有环境和角色。

### 1.2 运行结果与用例结果分开

统一回执包含运行标识、实际模块版本与摘要、目标及上下文摘要、执行状态、实际业务响应、完成检查、数据完整性、结束状态、证据引用、耗时与工具调用数。详细日志按需读取，不反复返回完整页面和源码。

| `execution_status` | 含义 |
| --- | --- |
| `completed` | 已完成契约声明的操作与观察；可以观察到正常结果、空结果或业务校验拒绝 |
| `blocked` | 前置条件、工具、环境、资源或适用验证范围不足，无法继续本次操作 |
| `failed` | 页面交互或读取没有按契约完成；保留具体阶段，不自动判为产品 BUG |
| `unknown` | 已触发写入但是否生效不明；保留关联标识并先回查 |

写入回执另记录是否尝试，以及已应用、明确未应用或结果未知；组合流程保留每个已触发写动作的结果，不用整体失败掩盖已发生的写入。这些是 UI 回执设计，不改现有运行器的枚举值。

空历史必须在目标区域就绪且明确为空时返回完整的空集合；区域缺失、尚未加载或只读了第一页不能伪装成无历史。业务拒绝是观察结果：负例可能因此通过，正例可能失败，由场景预期决定。通用比较可以复用，但期望内容来自用例及其依据，不根据实际值反向生成。

完成检查按实际响应分支执行：接受分支核对保存或流转，拒绝分支记录校验内容并核对写入状态；不能要求所有负例都进入保存成功分支，或仅看到错误提示便断言没有任何写入。

### 1.3 咨询历史示例

`orders.client.consultation.read-history` 是本规范的候选能力示例，不代表当前实现或真实项目规则：

- 开始：指定身份已打开目标子单详情，目标咨询卡片可定位，页面已就绪。
- 输入：本轮实际子单号、卡片标识、读取范围；默认读取调用方明确请求的范围，不默认等于全部历史。
- 动作：定位历史区域，按真实页面展开、翻页或加载内容。
- 输出：实际版本标识、文字及需要的附件信息、范围与完整性、证据；不凭空填充页面未提供的数据。
- 结束：停留在同一目标的历史区域，记录展开或翻页后的状态；不提交、审批或自动造数。
- 判断：模块证明实际读到了什么；“应有几条、顺序如何、应保留哪些内容”由具体用例判断。

## 2. 划分粒度

页面资料是观察和定位依据，不是可执行模块。可执行模块分为三种：component 处理确有复用价值的局部交互，action 完成一个有业务目的的动作，flow 组合多个已有能力。原生点击、输入等通常由适配器提供，不为每次点击注册模块。

| 咨询单操作 | 边界 |
| --- | --- |
| 查询指定子单 | 查询并返回匹配记录；可合法返回零条，不强制打开第一行 |
| 打开指定详情 | 目标已明确且唯一时打开，核对单据及就绪；不顺带修改 |
| 读取历史 | 从明确详情和卡片读取实际历史，报告范围及完整性 |
| 填写选型需求 | 填写并回读实际输入，停在未提交表单；输入截断作为实际现象返回 |
| 提交咨询单 | 触发一次提交，观察校验与保存／流转，记录是否生效；超时不重复提交 |
| 查询并读取历史 | 组合查询、打开详情和历史读取，显式传递目标标识及输出；不复制子模块代码 |

拆分依据是复用价值、独立前置／结束状态、不同业务效果、角色或资源边界。提交、审批、删除等持久化动作默认各有明确调用边界；批量提交作为一个显式批量动作，返回逐项结果，不假设全成或全败。

同一身份、同一页面任务中的紧密动作可以组合。跨角色场景由用例编排交接身份和真实单据，底层模块不隐式换账号或跨环境。多写流程逐项核对结果，遇阻停止后续动作；流程 effects 必须覆盖子模块全部副作用，不能将含 write 的组合标为 read。

一条用例保持独立的准备、编号步骤和预期。公共模块不决定测试场景的合并，也不把整项需求固化为一个长脚本。

## 3. 存放与检索

Skill 包保存规则、模板、索引及调用所需的通用工具；用户工作空间保存项目资产。以下是新工作空间的规范位置，按内容建立；已有目录通过显式映射接入，不复制成第二份权威来源。

```text
工作空间/
├── projects/<项目>/
│   ├── ui/
│   │   ├── pages/<系统>/<页面>.md
│   │   ├── modules/<系统>/<业务域>/<能力名>/
│   │   │   ├── capability.json
│   │   │   └── run.mjs
│   │   ├── verification/<模块ID>/<版本>/<记录ID>.json
│   │   └── catalog.json
│   └── requirements/<需求>/runs/<运行>/
│       ├── ui-usage.json
│       └── evidence/
├── shared/ui/
│   ├── modules/<业务域>/<能力名>/
│   ├── verification/<模块ID>/<版本>/<记录ID>.json
│   └── catalog.json
└── .local/                         # 本机凭据、会话与可重建运行缓存
```

`run.mjs` 是默认 JavaScript 实现文件示意；实际文件名和运行方式由 entry 声明，只有已实现的适配器才能运行。创建契约不能代替安装或实现适配器。

页面资料记录页面身份、可见控件及状态、适用角色、观察来源与时间，并区分旧页面实查、需求规定、推导和新版本实查。实际业务数据不写入共享说明。需求 evidence 保存本轮事实；包含受限数据的证据可留本机授权位置，由受管引用及备份范围说明其位置，不要求全部进入 Git。

catalog 由契约、验证记录及目录映射生成，可重建，不手工改成已验证。摘要只包含 ID、标题、用途关键词、范围、效果、版本摘要、验证适用性和资源引用。先筛项目、系统和目的，再按需展开候选；只搜到资料时按资料读取，不伪造可执行入口。

共享使用显式引用和精确版本。项目既有引用优先保持；没有引用时先查本项目，再查已允许的共享范围。候选都匹配时优先选择副作用最小、验证范围最贴近目标且满足测点的能力；仍有歧义才补问，不按标题相似度直接调用。

任务的 ui-usage 记录用例版本／节点及步骤、模块 ID／版本／摘要、依赖、参数来源、实际运行、证据和结束状态，可派生引用索引。正式用例仍展示人可读页面动作，不把代码、选择器或内部 ID 混进评审正文。

## 4. 从取证形成可复用模块

1. 保存本次实际观察及来源，先查现有资料和能力。新页面未部署时只形成资料和候选操作，不伪装完成取证。
2. 明确需要新增还是修订、操作边界、数据参数和副作用；有复用价值或可显著减少重复判断时再实现，不为凑目录生成脚本。
3. 写契约与实现，定位、等待和目标检查依据真实页面；对未知分支明确停止，不用接口或内部状态修改绕开被测 UI。
4. 做本地解析、引用、依赖与输入检查，再在已授权的环境、身份和数据范围内验证真实操作。业务写操作仅在已授权范围执行，代码生成不自动获得造数或提交权限。
5. 保存限定验证范围及证据，登记索引和引用。第一轮至少验证目标正常路径及本能力实际重要的停止条件；例如找不到唯一单据时不打开错误行，写入未知时不重复触发。没有“运行一次就支持全部场景”的规则。
6. 将操作说明同步给关联用例，将可复用能力登记给后续任务；分别记录取证、实现、模块验证与正式用例结果。

首次验证可在已授权的取证／测试范围内，以明确的模块验证任务运行新实现并取得证据；不能用“尚无 verified 记录”阻止首次验证。普通复用与模块验证的目的及结果分别记录，新实现不能先被计为已验证再补证据。

对本次上下文使用四种验证状态：not-verified（无适用证据）、verified（版本摘要与范围匹配）、stale（相关实现或页面依据已变化）、blocked（所需验证条件暂不可取得）。状态由记录和当前依据判断，历史记录追加保存，不抹掉原来通过的范围。停用能力另作退役标记，仍可追溯历史引用。

没有 QA 或平台首版时，可以完成需求场景和暂定步骤，模块停在资料或未验证实现；QA 部署后仅补采变化和缺口。正式执行需要的模块未就绪时按影响范围记录阻塞，不冻结整个需求分析与用例工作。

## 5. 后续复用与性能

一次调用依次核对任务归属和授权、固定版本及依赖摘要、环境／身份／页面条件、参数与测点、副作用、适用验证记录及资源占用，然后运行并保存回执。资料或验证不匹配时返回定向补采，不静默换环境、账号或模块版本。

首次使用或修订需读相关契约和证据；稳定路径由运行器加载代码并执行。模型默认读摘要和必要实际值，异常时再展开对应检查点。源码、完整页面及截图不用每轮反复输入模型；缓存须绑定版本摘要和本轮会话，不能缓存另一个项目的当前身份。

保留身份、目标唯一性、页面就绪、输入实际值、关键跳转及保存回读等必要检查，按本操作目的选择，不要求每次点击都截图。布局、遮挡或样式本身是测点时必须保留相应视觉观察；提速不能跳过测点或被测认证、上传、下载等真实交互。

咨询单复用规则示例：

- 改文重提和多次退回可以共用历史读取，分别传入本场景数据和预期；返回记录不能硬编码为两条。
- 会重置筛选的查询模块不用于验证筛选保留；无需给模块增加绕过检查的开关来强行复用。
- 负例校验被拒绝但页面响应已观察完整，可以 completed；由用例判断拒绝是否正确。
- read 模块也可能改变展开和导航状态，必须声明，不能关闭其他任务的未提交表单。
- 准备数据可复用公共流程，角色交接和业务标识保持真实；当查询、登录等本身为测点时不能用其他入口跳过。

每个运行回执记录工具调用数、耗时、返回体积及证据保存情况。实际 token 指标可得时记录，否则只注明文本量或估算；以相同场景、数据和检查点对照，不能仅以输出变短宣布整体提速。

## 6. 更新、版本与长期维护

模块实现版本采用主／次／补丁版本号，独立于产品发版版本和契约 schema：兼容的定位／等待修复用补丁，兼容的新输入输出用次版本，改变前置、输出语义、副作用或移除支持范围用主版本。验证范围增加可以新增验证记录，不要求改同一份代码的实现版本。

一个版本一旦被验证记录或任务引用，其契约和可执行文件即冻结，不同内容不能沿用同一 ID＋版本。纯页面资料补充保留资料修订，不为未变化实现制造新验证。来源摘要覆盖契约、执行文件和执行所需资源；验证记录置于其外，避免摘要自引用；任务另外固定依赖的版本和摘要。

可恢复来源必须是固定 Git 提交或受管的不可变快照，不能仅保存一个散列或会变化的磁盘路径。没有版本库时先保存受管快照；有版本库时同时核对引用可取得。备份包含被任务引用的版本来源、验证记录和必要证据，丢失来源明确报缺口；不把 .local 可重建缓存当成唯一历史。

更新流程：识别差异及受影响范围→查引用与正在工作的任务→补采→修订契约／实现及版本→核对依赖→最小适用路径重验→登记新记录→按授权更新用例和调用引用。已执行结果保持原依据，必要时标待复核；模块更新不会自动复测、更新整轮通过数或提交 BUG。

| 情况 | 处理 |
| --- | --- |
| 名称、布局或交互变化 | 保留差异，定位受影响模块与步骤；适用依据失效时标 stale，修订并验证 |
| 业务语义变化 | 返回 3.1 澄清，更新受影响用例预期；不只修选择器 |
| 权限、数据或网络不足 | 保留实际阻塞，不为绕过问题扩大权限或改输入 |
| 页面业务异常 | 返回实际现象与证据，由场景判断；不迁就实际结果改预期 |
| 写操作结果未知 | 保留原操作关联，先查同一目标是否生效；不重复提交、自动回滚或用修复流程重放 |
| 已退役或来源不可取得 | 阻止新任务默认选用，保留旧引用和缺口；不自动替换为“最新” |

活跃任务继续使用其固定版本，但每次仍检查当前页面是否适用；固定版本不保证新页面兼容。必须升级时记录原因、重新加载实现、保留断点及数据状态，不在一段组合流程中热替换代码。

多会话按模块 ID／文件范围明确单一修改负责人，提交前核对基线；索引由完成后的文件生成，不能混入其他任务半成品。浏览器、账号及业务对象按任务协调占用，不因模块是只读就允许两个执行者同时导航同一页面。通知和自动监听仍依宿主能力及用户授权，不承诺未实现的后台服务。

## 实施与验收边界

本文件确定六项设计，后续进入 3.3 用例编写的设计；第 4 步梳理真实工具、依赖、运行适配与能力缺口，第 5 步按授权实现。格式验证器、索引生成器、调用器和回执映射要遵循本规范，但本轮不声称它们已经交付。

后续行为验收至少覆盖：资料不能冒充实现、未验证能力不能继承其他范围通过、正常与空结果、负例业务拒绝、输入不被偷偷修改、筛选副作用不破坏测点、完整性与分页、未知写入不重放、版本漂移与引用更新、共享范围与多会话资源、历史来源恢复、包升级保留项目资产及同条件性能对照。先做合成与本地检查，真实页面验收另按授权；不新增与本轮无关的业务操作。
