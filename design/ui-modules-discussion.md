# UI 模块：早期讨论记录

日期：2026-11-02。状态：历史讨论记录。用户随后明确授权由 Agent 决定并确定六项 UI 模块设计，当前有效依据为 [UI 模块规范 v1](ui-modules.md)。本文件保留先前建议，不再是待确认工作入口；定稿不等于实现或真实验证。

已确认的上位原则见 [页面取证](stages/page-discovery.md)：按需取证，同时维护真实用例步骤和可复用操作能力。以下是具体内容与粒度的讨论建议。

## 建议的粒度

一个模块封装有明确目的、输入和结束状态的可重复页面操作；用例组织这些操作，并判断本场景业务结果。咨询单的候选拆分：

| 模块 | 操作与结束状态 |
| --- | --- |
| 查询指定咨询子单 | 输入子单号、查询并返回目标记录及匹配结果 |
| 打开指定咨询单详情 | 对明确记录进入详情，核对身份、单据和页面就绪 |
| 读取咨询历史 | 定位、展开、读取历史内容，返回记录和是否完整读取 |
| 填写选型需求 | 填入参数并回读，结束于未提交表单 |
| 提交当前咨询单 | 发起一次提交并核对保存或流转，返回实际结果及标识 |

填写与提交分开便于输入、草稿和取消场景复用；紧密的点击输入框、填值和查询可在一个动作内，不为每次点击建模块。常用组合可以调用已有模块，不复制实现；独立测试场景仍各有准备、编号步骤和预期。

## 最小内容建议

模块包含身份与归属、用途和适用范围、前置条件、输入、实际操作与等待、输出与结束状态、操作影响及异常处理、限定条件下的验证依据。具体字段、机器可读 schema 和目录未定稿。

可沿用 `capability.json` 加执行代码的形态。页面说明由相关能力共用，截图和运行记录通过引用关联；单号、凭据、临时 pageId 或快照 uid 不写入公共代码。

“读取历史”示例需要说明目标咨询卡片、数据身份、页面就绪、展开或分页、记录及完整性。只读取当前页不能声称已读取全部历史。

## 从取证到模块

先保存实际路径、条件及证据，再查已有能力，确定新操作的开始与结束；将本轮数据参数化，保留定位、等待和目标检查；对实现做适用范围内的实际验证，再登记验证条件。

只有原型或需求时可以保存操作设计，不能登记为已验证能力。实现变更后不能继承旧代码的已验证状态。

原工作台已有按子单号查询并核对详情的组合能力，可作为设计参考；此次并未将该业务脚本复制或注册为通用 Skill 模块。新增历史读取等只是候选设计。

## 复用与用例判断

两条用例可以共用查询、打开和读取历史，分别提供其准备数据及预期。模块回报实际记录、读取范围和证据，场景按确认规则判断。通用比较可复用，预期值仍由调用方提供，不在模块中固定“必须有两条历史”。

查询模块如果会重置筛选，就不适用于验证“返回后保留筛选条件”的场景。选择模块应核对实际行为、状态和副作用，不能只匹配名称。

正式思维导图继续展示人可读的页面动作；模块 ID、版本和步骤映射可以另存关联记录，不把用例正文缩成“调用某模块”。

## 速度与回执

从索引检索能力，核对简短契约和本轮条件后参数化调用。正常返回目标、动作结果、实际数据摘要、读取完整性及证据入口，细节按需展开；用例所需判定数据不能为缩短返回而丢失。

稳定路径不要求每步重复视觉推理；仍检查身份、目标、页面就绪和结果。陌生交互、定位变化、异常或视觉测点再定向补采。模块完成不自动等于业务用例通过。

## 更新方式建议

- 名称或定位变化：补采并修订实现与步骤，在适用范围验证后更新模块版本。
- 页面结构变化：调整动作及开始／结束状态，检查组合流程和用例引用。
- 业务语义变化：回到需求澄清并更新受影响预期，不能仅改选择器。
- 权限或环境不满足：保留实际阻塞，不把所有问题当定位失效。
- 输入截断等业务异常：报告实际内容，不改测试输入来追求模块成功。

保留旧版本、证据和变化原因，明确调用方采用的版本；进行中任务不静默切换实现，旧结果保留当时依据。写操作结果未知先核对是否生效，不为修复模块重复提交。

粒度的讨论检查：能否单独复用，输入与结束状态是否清楚，修改后能否识别受影响调用方。本文件仅保存原讨论，后续按定稿规范推进，不反复要求用户确认已委托决策的六项设计。
