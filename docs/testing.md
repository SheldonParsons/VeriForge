# 候选版验收

本候选版先验证本地实现、安装包与契约，再由真实 Agent 在用户授权的项目中验证行为。不要把合成数据的结果计为业务测试通过。

## 已纳入自动检查

- 多项目同号需求、修订冲突、历史摘要、受管路径、锁和共享版本。
- 旧格式原始记录校验、只读不迁移、显式升级与旧历史保留。
- 证据前置、扩展执行状态、BUG 去重统计、同步与业务结论分离。
- 备份覆盖、敏感快照排除、新目录恢复、恢复后执行保护。
- 凭据加密、错误密钥、范围不匹配、禁止存入工作空间/Git、普通记录拦截。
- 历史知识查询计划、项目范围、来源冲突与缺失提示。
- 写动作不重复派发、未知结果不清除、原确认交互续接、来源和配置漂移。
- 本地 HTTP 服务的成功、业务不符、同源回读、跳转、断线与禁止写方法伪装只读。
- Mind 目标映射、保存回读条件、UI 模块范围、截图标注和 BUG 图片位置。
- 包内链接、版本、公开内容模式扫描、图片摘要、独立解包安装与命令走读。

## 真实 Agent 验收顺序

| 场景 | 输入 | 验收关注点 |
| --- | --- | --- |
| 第一次安装 | 候选 ZIP + 新测试目录 | Agent 找到实际安装位置，依赖可装，能解释用途；不先要全部账号 |
| 新成员补背景 | 一个真实已授权项目 | 主动读相关 KB / Nexo，来源正确，只问关键缺口；不串项目 |
| 新需求无 QA 页面 | 需求原文与原型 | 可以先写有依据的场景；步骤标待核实，不编造取证 |
| 完整用例编写 | 一项范围小的需求 | 可读、按场景编号、步骤可执行，有少量完整链路和历史回归 |
| 页面可用后补采 | 专用 headless 浏览器 | 核对真实控件，更新用例及 UI 模块；不影响日常浏览器 |
| 执行和 Mind 标记 | 小批已评审场景 | 正确判定，实际保存后读回标记；失败数与 BUG 数分别统计 |
| BUG 提交与复验 | 已授权缺陷平台的测试项目 | 简洁文稿、标注图片、身份与字段正确、图片正式关联且他人可见 |
| 知识入库 | 用户确认稳定的需求 | 展示具体预览，获得确认后写入并读回；取消不写 |
| 多会话续接 | 中途暂停或工具断线 | 保留任务、未知写入及资源；新会话不盲重试 |
| 图文与跨宿主 | 实际使用的 Agent 客户端 | 导航图片能否显示、路径与安装流程能否适配，逐项记录 |

每轮记录宿主、版本、系统、验证范围、证据和未通过项。账号只放私密库或宿主安全配置。发现问题后补针对性的自动检查，再重复受影响项，避免每次无差别重测。

## 待验证边界

当前本地自动测试使用模拟服务和虚构数据。真实知识库写入、思维导图保存、浏览器业务链路、禅道图片归属、独立账号访问、不同操作系统以及不同宿主的实际安装和行为，需要分别验收。Node 命令可运行不等于完整测试工作流已通过。

## 发行前另行确认

正式发行前确认整体许可证及外部图片分发授权，审计拟公开仓库的历史和包内容，并选择受支持宿主/平台。当前源码导出包不含 Git 历史；清理当前文件并不会清除历史提交。不要未经授权重写共享仓库历史。
