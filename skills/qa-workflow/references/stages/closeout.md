# 阶段收尾与复盘

用户说“这轮先收尾”“交给同事继续”时，先核对实际范围、结果和未完事项。阶段结束、暂停、整个需求结束分别记录，不把用户查询状态当成结束任务。

默认交付：正式用例、最终或候选知识内容及其状态、用户本次指定产物。不默认额外生成成套报告。把结论和入口写入现有需求记录；没有人工 README 时可用 summary.write 生成可重建摘要，已有人工内容不覆盖。

## 核对什么

- 本轮已测、通过、失败、阻塞、待核验及未执行，固定统计范围，重试不重复计数。
- 每条失败对应 BUG、候选或解释；BUG 数和失败场景数分别统计。
- 上线、短期稳定确认、知识同步和临时资源恢复分别说明。
- 产物与证据版本可定位，远端动作有实际回执；外部 URL 不代表已经备份。
- 临时数据、权限、配置按既有约定恢复，不清除唯一复现证据或覆盖他人后续修改。

例如 20 个场景已执行，18 通过、2 失败关联同一条未修 BUG，尚未上线：可以结束本轮交接，保留失败与复验待办，知识候选稿先在本地；不能称整项需求全部通过或已入库。

## 接续与归档

用 deliverable.set 关联正式快照，用 followup.record 写清未完事项、状态、下一步和已知负责人引用。负责人字段不是给同事发消息或自动派工。接手先核对旧执行停止、未知操作与资源，恢复后从明确断点继续。

归档不删除原文、历史和证据，不清除待办，也不改变 BUG 状态。恢复副本继续受旧执行核对约束；本地保存、Git 同步、外部写入和独立备份恢复分别报告。

分析结束、评审完成与测试收尾做简短复盘，依据本轮真实遗漏、重复工作和证据问题提出少量改进。没有新增问题就注明，不重复长问卷。关键漏测或来源冲突发现时即指出，不等收尾。

通用规范调整由明确负责者或治理会话综合处理，保留版本；不因一次局部经验批量改写历史用例。只有实际测量过才谈耗时或 token 改善。

交接用[轻量模板](../../assets/templates/handoff.md)，遗留事项保持可检索；下次用户说继续时核对当前部署与状态，不重新执行整轮。
