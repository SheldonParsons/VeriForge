# BUG 复验

用户在复验语境只给链接也可开始。先读取最新工单、截图、状态、修复说明和关联需求，再找本地用例与失败证据；缺什么只问什么，不要求重讲需求。没有本地用例时建立最小复验场景，不先补整套导图。

影响版本不是修复部署版本，“已解决”不是测试通过。核对实际环境、部署依据、角色、数据和正确预期；不能静默换环境或借当前页面改预期。

## 范围与结果

保留原问题的关键触发条件。原证据清楚时可直接测修复后的版本，不必切回旧版先复现。旧数据不可用时按授权准备等效条件，差异影响结论时注明覆盖不足。

验证原问题，再按影响选必要回归，每项说明理由。例如备注未回显，核对有备注记录、修改保存后再打开、适用的空值状态及同表单字段。跨角色咨询历史问题可选择创建、驳回、修改重提、审批和终态回查的代表链路，不扩成全项目重测。

原问题与必要回归分别记录：仍失败不关闭；必要范围阻塞时只报告局部通过；偶现未出现但条件不足不认定已修复。另一个独立问题单独关联，不要求整个项目无 BUG 才能关闭当前问题。

## 关闭与接续

只有具备关闭授权、适用验证依据和当前状态允许时才通过 API 关闭并回读。已授权“通过后关闭”不再逐条询问；只说复验不自动关闭或发表远端评论。明确由用户验证后要求关闭时，说明依据来自用户。

不能替开发先置已解决来满足关闭接口。关闭超时先查询；他人已关闭时按实际动作归属报告，不将其记成本次执行。复发、重新激活按实际授权处理，不重复建单绕过状态流程。

保存本轮环境、规则／用例版本、范围、结果、证据与未完成项。原失败历史保留，新通过追加。只改完整执行通过的场景标记，部分步骤通过或仍受其他 BUG 影响时不把整条改成 100。

UI 新信息继续维护到模块；关闭不自动触发知识库写入。用 followup.record 保留待部署／补数据／复验事项，跨会话接续见[状态与协作](../operations.md)。
