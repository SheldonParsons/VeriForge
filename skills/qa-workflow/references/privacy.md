# 凭据与私密资料

VeriForge 将安装包、工作空间和私密存储分开。

| 位置 | 保存内容 | 进入普通备份 |
| --- | --- | --- |
| Skill 目录 | 通用规则、JavaScript、模板、导航图片 | 随安装包分发 |
| 用户工作空间 | 项目、需求、阶段、证据、产物和凭据引用 | 仅受管记录与已登记快照 |
| `~/.veriforge/private/` | 加密的账号密码、Token、必要的私密证据 | 否 |
| 宿主安全配置 | 原生 MCP 所需的环境变量或凭据 | 由宿主负责 |

## 内置本机凭据库

`VERIFORGE_PRIVATE_DIR` 可指定另一个私密目录。运行器拒绝把它放进 Skill、工作空间或任何 Git 仓库。目录权限使用 0700、文件使用 0600；Windows 的 ACL 仍需宿主和系统保障。

每个凭据带工作空间、被测项目、系统、环境、服务及可选角色范围；HTTP 执行前按范围解析。`secret.put` 写入，`secret.list` / `secret.status` 只返回字段名和配置状态，不返回密码。加密采用 scrypt 派生密钥和 AES-256-GCM；密钥由 `VERIFORGE_VAULT_KEY` 提供，应从用户本地密码管理器注入，使用随机高强度值。最低长度校验不能保证密钥强度。

通过受控标准输入提供 `secret.put` 请求，不把真实值放在 shell 命令参数、示例 JSON 或聊天回复中。包含 `value` 的请求仅用于这次本机调用。普通状态只存 `credential_ref`。运行器检查常见敏感字段；它不是通用 DLP，文本段落、任意附件和截图仍需检查。

```json
{
  "action": "secret.put",
  "actor": "lead",
  "ref": "example-qa-api",
  "scope": {
    "workspace_id": "从 workspace.json 读取",
    "project": "example",
    "system": "web",
    "environment": "qa",
    "service": "http",
    "role": "tester"
  },
  "value": {"token": "仅在受控输入中替换"},
  "expected_revision": 0
}
```

账户可以用于禅道、AsyncTest 或任意被测系统，但不同服务必须分别配置。原生 MCP 由宿主连接，本机凭据库不会自动把解密值写入宿主配置，也不承诺跨客户端自动注入。宿主已安全保存时优先复用，避免保存两份。

## 备份与轮换

普通工作空间备份明确排除凭据库；用户需要另行备份加密目录，并通过独立安全渠道保管密钥。换密钥前用旧密钥解密并在新的私密目录重加密、验证；本版不提供一键轮换。丢失密钥无法恢复原值，应重新申请密码或 Token。

密钥通过环境传入，和当前进程同权限的本机程序仍可能访问。该库解决的是源码、工作空间和普通备份的分离，不是对受控主机上其他同权限程序的安全隔离。

BUG 文稿默认用账号引用；若用户明确要求向授权的工单提供测试密码，只在所选私密渠道临时填充，回执脱敏，不能将其回写通用记录或知识库。
