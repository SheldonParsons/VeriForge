# UI 资料与模块复用

页面资料用于描述实际入口和控件；可执行模块需要真实实现、契约和限定验证记录。本包提供维护规则，尚未交付 UI 契约校验器、统一执行器或任何平台业务模块。

模块按独立操作划分为 component、action、flow；查询、打开详情、读取历史、填写和提交可分别复用。填写与持久化写入分开，流程组合现有模块，不把整项需求变成长脚本，也不合并独立场景。

每份契约需要稳定 ID／版本、项目或共享范围、系统环境、实际入口、前置、类型化输入、输出及完整性、read／draft／write 效果、完成检查、恢复规则、固定依赖和限制。ID 不包含账号、需求编号或环境；共享范围明确，平台相似不等于可复用。

页面资料、模块源码、验证记录与本轮测试证据分别保存到用户空间，现有目录可映射；不把公司选择器、账号或单据写进通用 Skill。索引由真实资料生成，按项目、系统和用途定位，再展开必要契约，避免每次读取整库。

形成过程：保存观察 → 查重与确定操作边界 → 参数化实现 → 在已授权条件验证 → 登记版本及适用范围。无页面时只能保留草稿；人工走通不证明新代码可用。首次验证允许在相应授权范围进行，不能要求先 verified 才能验证。

复用前核对版本摘要、依赖、环境、身份、页面条件、数据来源、测点、副作用和资源占用。全局 verified 不覆盖其他角色或环境；模块只返回实际结果，具体预期来自用例。合法空结果或业务拒绝可以是操作完成，不能一律当脚本失败。

真实执行中的有效观察及时保存，在场景／批次边界整理；不在活跃链路中热换模块。变化只影响有关版本和引用，旧测试结果保留原依据，必要时标为需复核。

首版调用原则是本地动作准备、宿主原生 MCP、真实回执登记。现有 operation 命令只保存意图，不能冒充自动调用；本包未实现的动作计划 API 不得自行编造。已有适用模块可通过当前宿主支持的调用方式运行；优化不得绕过审批、停止机制或真实 UI 测点。

默认简洁回执，完整源码与证据按需读取；保留身份、唯一目标、页面就绪、输入回读和业务结果检查。布局本身为测点时仍需视觉核对。性能变化要同场景同断言测量，文本变短不等于整体耗时或真实 token 已降低。
