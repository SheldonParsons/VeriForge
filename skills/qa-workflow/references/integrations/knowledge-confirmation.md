# asynctest-kb 的预览与恢复

接入信息见[AsyncTest 指引](../asynctest-setup.md)，正式沉淀时机见[知识阶段](../stages/knowledge.md)。依据当前实际 schema 与服务回执，不能自行编造参数或确认工具。

新请求明确项目和最终正文；后续 interaction_response 使用原工具、真实 pending_id 和用户对该具体预览的选择，不混传新请求参数。原生表单由宿主承载；服务返回普通 input_required 时，Agent 展示完整预览与选项，取得回答后按 continue_with 继续。

当前已核对的协议中，apply 是确认、cancel 是取消；submit 表示补充信息后由调用方重新整理完整参数，不等于提交知识；preserve 可能产生新的原文预览，仍须按真实回执继续。不能仅凭动作名称推断已经写入。

记录正文版本、项目、原工具、凭据引用、预览身份、到期信息、用户选择、派发与提交引用。服务权限、预览归属和有效期按当前结果核对；换会话或凭据后不假定旧预览有效。

有 pending、inputRequests 或 need_info 时，即使旧版外层状态写 completed，也先按未完成交互处理。确认超时先查询变更记录的 confirmation_id 和对应正文，避免重复提交；pending_resolved 仅说明已处理，可能不是成功。查询无结果或相同正文都不能单独证明这次操作是否生效。

取消后停止该项，不反复发起。过期或 stale 时先核对当前内容和是否已有提交，再按新的明确基线准备预览，不能给正文添加无意义字符绕过幂等保护。服务索引更新与正文提交分别核对。

只有实际提交和回读成功才能登记 synced；本地快照与 workflow.record 不写知识库。当前包没有内置 MCP 确认转发器，按宿主实际能力处理；无法完成交互时保留正文与具体待办，不绕过服务改数据库或调用私有写接口。
