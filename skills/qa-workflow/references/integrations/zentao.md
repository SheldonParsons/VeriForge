# 禅道 API 方式

按项目的真实实例协议、认证和字段映射使用。默认 API 创建及关闭，用户另有明确方式时按其要求；方法约定不扩大本次 BUG 范围。本包未内置通用提单客户端，有合适现有工具时才在授权内执行。

已登录同源会话和独立 Token 是不同认证配置，分别核对身份及权限。同源会话承载 API 时仍遵守 headless；不导出 Cookie，不把 safeStorage 密文当密码，也不从旧样本复制公司对象 ID。

典型 v1 路由基线为：身份 GET user；Token POST tokens；图片 POST files；创建 POST products/{productId}/bugs；读取 GET bugs/{id}；补齐 PUT bugs/{id}；关闭 POST bugs/{id}/close。实际前缀、编码和支持字段按实例核对，不能失败后自动换 v2 重发。

旧实例中有同一认证会话、同一事务 uid 的 REST 上传与创建图片绑定经验，关闭曾使用 multipart comment + uid；这是适配线索，不是所有部署的保证。事务上下文从实际受控来源取得，不随机生成或复用用户正在编辑的表单 uid。

操作顺序：核对稿件／身份／映射及重复 → 保存派发依据 → 上传真实标注图 → 创建一次 → 回读正文、字段和文件正式关联 → 核对实际图像内容。字段补齐只改同一 BUG，用户的最新正文不能被旧稿覆盖。图片放在结果内，期望之前；本机路径不能作为远端图片。

关闭按复验与用户授权，读取最新状态后执行并回读；不能替开发先置已解决。超时或中断先查原对象和动作记录，不重建或重复关闭。他人已关闭时如实报告动作归属。

验证图片区分文件上传、正式绑定、保存后可读取和有权限独立账号可见；仅 HTTP 200 可能是错误 HTML，需检查类型和解码等实际内容。独立可见性按首次接入、链路变化和用户要求核对，不继承上传者缓存结论。
