# 说明与使用帮助

用户可先了解 Skill，也可直接开展任务。先回答当前问题，必要时给一个例子。普通介绍不要求用户提供编号、账号或完整材料，也不创建任务、修改状态或索取凭据。

## Skill 是什么

> 这是一个面向 Web 测试工作的协作 Skill，帮助你组织项目资料、进度和测试记录，也方便换会话或交接后继续。你直接说眼前要做什么就可以。

## 能帮我做什么

按 [本包能力说明](../assets/capabilities.json) 回答当前可用范围，勿将未来能力固定写进每个回答。也可调用 `qa.mjs --capabilities`，命令不访问或创建用户工作空间。

先结合用户目标说明包内业务阶段指引、模板与接入图文，以及项目、独立事实、产物、遗留事项和备份记录。真实页面、导图、知识库和缺陷平台仍需要适用规则、实际工具与任务授权；本地动作日志不自动调用 MCP；`http.execute` 可在明确配置和授权下发送 HTTP 请求。代码存在、工具可见和业务验证通过分别表达，不声称已在所有宿主和独立 Agent 上验收。

## 流程怎样

解释用户开展测试的流程：需求澄清 → 按需页面取证 → 用例编写与修订 → 测试执行 → BUG 处理与复验 → 阶段交付；取证可随时补充，用例写完可直接评审，不单列 Skill 必经关卡。过程结论持续本地记录；本期完成、正式上线并确认短期稳定后强烈建议沉淀到 asynctest-kb，减少重复解释并方便交接追溯。尚未上线也可阶段收尾，保留知识待办；不能仅凭测试通过推断已上线。

用户可以从现有用例或待验证 BUG 接入，每次只推进已指定范围。不要求从头开始，也不因问流程就自动执行。除非询问开发进度，不展示开发本 Skill 的研发路线作为使用流程。

## 其他常见问题

| 用户问题 | 回答重点 |
| --- | --- |
| 第一次用怎么开始 | 先看已有资料，必要时补问当前系统和任务，不要求学配置格式 |
| AsyncTest 怎么下载、MCP 信息在哪 | 按[图文指引](asynctest-setup.md)说明下载和服务侧取信息位置，再由当前 Agent 适配；已有可用连接时复用 |
| 已有用例能继续吗 | 从对应工作接入，先核对版本、环境、角色、范围及工具 |
| 要先装全部 MCP 吗 | 只核对当前任务需要的能力；无法使用时说明影响和必要设置 |
| 能多项目、多会话吗 | 分别说明本地归属与协作记录，以及宿主派发能力与授权条件 |
| 文件在哪，做到哪里了 | 定位目标后读取实际资料和状态，不用通用问答猜进度 |
| 会自动提 BUG 吗 | 依本次请求及已有约定，普通能力咨询不授权外部写入 |
| 换电脑或误删怎么办 | 说明实际保存、备份覆盖和恢复点；不承诺不存在的后台同步或绝不丢失 |
| 用例已完成但页面还没有上线怎么办 | 分别登记内容可评审、页面步骤待核对与执行准备，后续定向取证 |
| 这轮测完还有 BUG，能收尾吗 | 保存实际结果、遗留与恢复事项，可以阶段交接，不能称需求全部通过 |
| 怎么找到交付文件和下一步 | 用 deliverable.list、followup.list 或 resume 查看固定快照及未完事项 |
| 从旧版升级会覆盖资料吗 | 新版可只读旧格式；使用新记录前单独升级根标记，保留旧修订，先核对备份和旧执行 |

工作中的插问不清空任务，也不自动暂停；答复后继续原授权工作。明确暂停的任务不会因普通问答自动恢复。用户用问句提出具体操作时，结合完整语境处理，不只回答“可以”。
